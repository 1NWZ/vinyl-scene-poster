# 参考效果拆解：Summer Swim 场景唱片

## 观察范围

本说明来自用户提供的 11.2 秒、1080 × 1440、30 fps MP4，对全片按约半秒间隔抽帧并查看细节；文件只有视频流。文件名带有“AI+p5js制作流程”，但这段素材实际展示的是持续运动的成片，没有可核实的源代码、AI 提示词或制作界面。以下区分直接观察与为可复用 skill 提出的设计建议。

参考来源署名：用户提供文件名中的“梦见两只电子喵／小红书”。本包不包含参考视频、截图、原曲目文字、作者标识或其源代码；没有据文件名推断公开链接。

## 一、效果的核心：唱片 × 泳池的双重含义

画面从俯视角呈现一张巨大蓝色唱片。蓝色圆盘同时是泳池；密集同心线同时是唱片沟槽和水波；黄色中心盘标把“音乐载体”身份保留下来；微缩泳客让盘面读成一个生活场景。右下方白色唱臂提供稳定的机械参照。

这是一个可以迁移的设计方法：**载体结构负责辨识，场景语义负责想象，尺度差负责趣味，持续运动负责吸引停留。**

可迁移公式：`一个熟悉的载体 + 一个来自照片的场景 + 少量微缩主体 + 一种主运动 + 一至两种环境运动`。

“胶片”通常指摄影胶片；这段参考更准确的视觉命名是“黑胶唱片场景海报”。清亮色块、环线、微缩人物和机械结构是主要特征；从这段压缩视频不能把细微纹理可靠地归因为真实胶片颗粒。

## 二、动态如何形成

| 层级 | 画面中可观察的表现 | 复用时的做法 |
| --- | --- | --- |
| 主旋转 | 黄色盘标及其文字持续逆时针转动，泳客也沿盘心公转 | 把盘面、盘标、文字和主要角色放入同一旋转组 |
| 固定结构 | 白色唱臂、右下轴座和画面边界保持稳定 | 在固定画布坐标中绘制唱臂，避免继承盘面变换 |
| 细节变化 | 星形水光、水面短线和盘内曲线随时间改变视觉状态 | 使用稀疏高光呼吸与有界的周期水线；无需让所有线条都动 |
| 观看节奏 | 画面一直维持同一构图，主元素持续运动 | 用一个可连续观看的循环组织整张海报 |

抽样帧中的标签角位移并非严格等间隔，因此不能断言原片为恒定转速，也不能从成片确认是程序调速还是后期处理。泳客的公转是明确可见的；独立的逐肢划水动画无法仅据这些画面确认，不应把复杂骨骼动作列为复刻前提。

6 秒整圈、30 fps、确定性循环是本 skill 的制作默认值，不是从参考源码得到的参数。用户若强调更贴近原片，可在主旋转中加入轻微周期速度变化，但要先保证循环边界连续。

## 三、配色为什么成立

这段视频采用高明度、高纯度的蓝黄对比，暖白缓冲，橙红点睛。

| 颜色 | 从抽样帧得到的近似参考值 | 作用 |
| --- | --- | --- |
| 水蓝 | `#008DE9`，邻近区域可见更深或偏青的蓝 | 占据大部分画面，将唱片读成清凉水面 |
| 柠檬黄 | `#FBED07` | 与蓝形成醒目的冷暖、明度和色相差，建立盘心焦点 |
| 暖白 | `#FAF7F2` | 作为画布与唱臂的大块缓冲，避免全画面高饱和 |
| 橙红 | `#D95A13`，为视觉近似值 | 用于主标题与少量人物装备，带来温度 |
| 深蓝黑 | `#102A3A`，为视觉近似值 | 用于轴孔、结构线、小面积人物细节 |

颜色受视频压缩、采样位置和光泽影响，上述数值不是作者原始设计色。近似面积关系可理解为：蓝色约六成，黄色一成多，暖白约两成，其他颜色少量。实际比例随裁切变化，不是固定约束。

迁移时保持“主色统领、大色块明确、少量对比点睛”的关系。咖啡可以转为咖啡棕与奶油白，花园可以用叶绿与浅粉，夜景可以用深蓝与暖黄；这些是创意建议，并非参考中出现的版本。

## 四、场景与版式

抽样画面的盘心约在 `(350, 606)`，外半径约 730 px，盘标半径约 250 px。对 1080 × 1440 画布，分别近似为 `(0.32W, 0.42H)`、`0.68W`、`0.23W`。这些是画面测读值，非精确工程参数。

- **巨型圆盘出血。** 顶部和左侧被画布裁切，右下仍可见暖白底色。画面更有临场感，同时给唱臂留下空间。
- **中心向左偏移。** 盘标成为视觉核心，但整张海报不呈现机械的居中对称。
- **斜向唱臂平衡圆形。** 从右下伸向盘心右侧，提供不同于环形轨迹的方向，也解释这为何是一张“唱片”。
- **人物很小。** 微缩人体与巨型盘面形成尺度差，使抽象蓝盘读成可以进入的泳池。
- **文字属于物件。** 主标题绕盘标排布，小号边标与曲目形式文字填充局部，文字随唱片运动。画面没有单独的大标题栏。
- **细节有共同语法。** 环线、星芒、短波纹、泳圈都服务于水面主题，不混入无关装饰。

版式的主要动线可以理解为：黄色盘标吸引注意 → 白色唱臂指向右下底座 → 蓝色圆盘与微缩人物将视线带回盘内。

## 五、单图玩法如何成立

本 skill 的输入是一张照片，输出不是对照片套一个统一动画模板，而是提取可辨认的“个人线索”并组织新场景。例如海边照片中的泳衣色和遮阳伞、宠物照片中的花纹与玩具、咖啡照片中的杯型和桌面配色，都可以成为盘内主体或环境材料。

每张成片至少要保留一个明确的来源锚点。若整张画面都能被另一张无关图片替换而没有变化，说明转译过度、个性不足。

默认由模型依据输入重新生成统一的垂直俯视场景；固定结构、精确字形、图层旋转与导出交给代码。这样文字可编辑、构图可控、时间轴可循环，也能避免逐帧生图引起的人物变形与素材闪烁。

## 六、实现中最容易出错的地方

| 问题 | 视觉后果 | 应对 |
| --- | --- | --- |
| 将原照片的斜视角物体抠出绕圈 | 容器与食物仍呈产品正面视角，无法读成统一俯视世界 | 先由模型重建 90° 俯视场景，检查圆形口缘、顶面与接触关系，再制作动画 |
| 直接旋转整张成图 | 背景与唱臂一起转，看不出机械层次 | 先拆成盘面组与固定组 |
| 只有完全对称的环线在旋转 | 数学上在动，视觉上几乎静止 | 保留人物、标题、短弧等不对称标记 |
| 给父层和角色重复施加同一转角 | 角色出现双倍转速或位置错误 | 明确局部坐标和全局坐标 |
| 每帧重建随机星点或位移 | 画面噪闪、无法顺滑衔接 | 初始化随机参数，用周期函数驱动 |
| 每次循环从空白开始积累尾迹 | 首尾水线密度不一致 | 由周期历史样本重建尾迹 |
| 文字跟随盘面整体拉伸 | 排版模糊、读不清 | 使用真实字体与圆弧排字，分层绘制 |
| 把同一主角复制很多次 | 来源关系变得机械、叙事失真 | 保持一个主角，用环境物件补充尺度 |
| 没有导出能力却承诺视频已完成 | 用户得到无法使用的交付物 | 先检测渲染编码能力，交付真实产物 |

## 七、技术核对来源

以下文档只支持实现约束，不用于推断原作者的制作过程：

- [p5.js rotate()](https://p5js.org/reference/p5/rotate/)：坐标系旋转、角度方向与绘图组隔离。
- [p5.js randomSeed()](https://p5js.org/reference/p5/randomSeed/)：固定随机种子可复现随机序列。循环还需要周期性时间函数。
- [p5.js saveFrames()](https://p5js.org/reference/p5/saveFrames/)：该导出方式当前列有 15 秒与 22 fps 上限，高清 30 fps 应另选确定性的渲染导出流程。
